# IC(R/W)-RRF v7.0 — PQAS Evaluation Results

*Generated from `evaluation/probe_pqas_*.py`. Run files: `data/trec-dl-2019/runs/`
and `data/trec-dl-2020/runs/`. All numbers reproducible.*

---

## Headline

**v7.0 PQAS significantly improves over v5.0 on TREC DL 2020 within-collection k-fold CV** (+0.0271 NDCG@10, p=0.003 paired t-test). Captures 49.5% of the per-query oracle gap on that collection.

**v7.0 PQAS shows no significant improvement on TREC DL 2019** (43 queries appears below the reliability threshold).

**v7.0 PQAS does NOT generalize cross-collection** — leave-one-collection-out CV fails in both directions due to feature-direction reversal between 2019 and 2020.

v7.0 is therefore a *label-light, per-corpus* tier, not a successor of v6.0. The lineage now offers parallel deployment options.

---

## Within-Collection 5-Fold Cross-Validation (5 seeds averaged)

| Collection | Vanilla | v5.0 | v6.0 REF | **v7.0 PQAS** | Oracle | PQAS captures |
|---|---|---|---|---|---|---|
| **TREC DL 2020 n=4** | 0.4483 | 0.4373 | 0.4393 | **0.4644** | 0.4808 | **49.5%** of oracle gap |
| TREC DL 2019 n=4 | 0.3645 | 0.3800 | 0.3832 | 0.3785 | 0.4106 | -5.1% (within noise) |

PQAS hyperparameters: l2=0.05 (2020), l2=0.30 (2019), classification threshold = 0.50.

## Paired t-tests on per-query NDCG@10

| Collection | PQAS vs Vanilla | PQAS vs v5.0 |
|---|---|---|
| 2020 n=4 | +0.0161 (t=+1.53, p=0.125, ns) | **+0.0271 (t=+2.93, p=0.003, \*\*)** |
| 2019 n=4 | +0.0140 (t=+0.73, p=0.466, ns) | -0.0016 (t=-1.00, p=0.317, ns) |

The TREC DL 2020 result is the load-bearing positive finding. p=0.003 against v5.0 is robust.

## Routing decisions (TREC DL 2020 best config)

Across 5 folds × 5 seeds = 270 total query-routing decisions on TREC DL 2020:
- 73 picks of v5.0 (~27%)
- 89 picks of Vanilla (~33%)
- Remaining: variance across seeds for queries near the decision boundary

PQAS uses both routing options actively. It is not collapsing to "always v5" or "always Vanilla."

On TREC DL 2019, the model picks v5.0 for ~95% of queries — it can find no reliable signal that consistently prefers Vanilla. This is the data-efficiency wall (43 queries is below threshold).

## Leave-One-Collection-Out CV (falsified hypothesis)

| Train → Test | NDCG@10 | vs Vanilla | vs v5.0 | vs v6.0 REF |
|---|---|---|---|---|
| 2019 → 2020 | 0.4412 | -0.0071 | +0.0039 | +0.0019 |
| 2020 → 2019 | 0.3800 | +0.0155 | 0.0000 (collapses to "always v5") | -0.0032 |

Neither direction beats the best fixed baseline. The feature-direction reversal between collections makes cross-collection transfer structurally impossible at the current feature set.

## Feature signature comparison

| frac_specialist_top30 | -0.047 | -0.070 |

| score_var_mean | -0.078 | -0.068 |
| mean_rank_dist | -0.032 | **-0.134** |

The two trained models load-bear on different features. The 2020 model uses score-distribution features (top1_spread, max_score_gap). The 2019 model uses rank-agreement features (rho, mean_rank_dist). Some features (score_gap) point opposite directions between the two collections. This is the structural reason cross-collection transfer fails.

## Falsification Record

Three hypotheses tested explicitly during the v6.0 → v7.0 transition:

| Hypothesis | Verdict | Diagnostic |
|---|---|---|
| Label-free multi-feature rules win on both TREC DL 2019 + 2020 | **Falsified** | Feature-direction reversal between collections; no threshold rule resolves it |
| Supervised PQAS transfers cross-collection via LOOCV | **Falsified** | Trained models leverage features that reverse direction between collections |
| Within-corpus supervised PQAS captures the per-query oracle gap | **Confirmed for 2020, not for 2019** | 2020 (54 queries, strong signal): +49.5% of gap, p=0.003. 2019 (43 queries, weak signal): no significant effect |

## Reproduction

```bash
# Within-collection k-fold CV (the main confirmed result)
python evaluation/probe_pqas_kfold.py

# Paired t-tests with 5-seed averaging
python evaluation/probe_pqas_significance.py

# Cross-collection LOOCV (Falsified Hypothesis 2)
python evaluation/probe_pqas_supervised.py

# Label-free combinator (Falsified Hypothesis 1)
python evaluation/probe_pqas_combinator.py

# Per-query feature diagnosis (the source of the oracle gap finding)
python evaluation/probe_per_query_diagnosis.py
```

All scripts use only Python 3.8+ standard library + the existing `trec_eval_harness.py` primitives. No external ML library required.
